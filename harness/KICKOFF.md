# KICKOFF — 他のハーネスで novel_studio を動かすための開始プロンプト

どのハーネスでも、渡す中身は同じです：**リポジトリ直下（または試験のサンドボックス）で起動し、AGENTS.md を読ませ、TASK.md か下の指示を渡す。**
ハーネスごとの違いは「AGENTS.md を自動で読むか」「長いコマンドの扱い」「権限の設定方法」だけです。

---

## 共通の開始プロンプト（そのまま貼る）

```
あなたは novel_studio の制作進行です。作業フォルダはこのフォルダです。

1. まず AGENTS.md を最後まで読んでください。次に TOOLS.md を読んでください。
2. TASK.md があれば、それがあなたの仕事です。なければ、私の次の指示を待ってください。
3. 道具はすべて JSON を返します。何かを「やった」と書く前に、必ず show / status / costs の JSON で結果を確かめてください。
4. 人の判断が要るところ（CANON の承認、上位モデルの呼び出し、resolve の accept/done、予算）では止まり、
   notes/REPORT.md に AGENTS.md 第3節の書式で報告を書いて、私に知らせてください。
5. 時間のかかる処理は `python3 studio/cli.py engine <slug> start` で切り離して起動し、2〜5分おきに status を見てください。
   同じコマンドを重ねて起動しないこと。2回失敗したら止まって報告すること。
6. してはいけないこと：.env を開く・表示する、承認を試みる、状態ファイルを手で書き換える、
   本文・CANON・審査結果を自分で書く、ウェブ検索・パッケージの導入・git・外部への送信。

始める前に、あなたが理解した「やること」と「止まるところ」を3行で書いてから始めてください。
```

最後の一行は、ハーネスが手順を取り違えていないかを最初に確かめるためのものです（Novel_4 の経験：指示を読んだつもりで別のことをするモデルがいた）。

---

## Hermes Agent

- **起動**：作業フォルダ（試験ならサンドボックス）に移ってから起動する。プロジェクトの文脈ファイルとして AGENTS.md を読むかどうかは設定と版によるので、**開始プロンプトの「AGENTS.md を最後まで読んで」を必ず残す**。
- **キー**：novel_studio の道具は `HERMES_CUSTOM_OPENROUTER_API_KEY` も探すので、Hermes 用に OpenRouter のキーを入れていれば、そのまま道具が使える（試験では偽モデルなのでキー不要）。
- **長いコマンド**：ターミナルの制限時間に掛からないよう、`engine ... start`（切り離し）と `status` の見回りにする。Hermes の定期実行（cron）を使うなら、「status を見て、canon_hold・escalation・done のどれかなら報告して止まる」だけを5分おきに、が安全。
- **VM で動かしている場合**：リポジトリをホストと共有フォルダにしているなら、git の操作はホスト側で（共有フォルダの git は、サンドボックス側からロックファイルを消せずに壊れることがある）。
- **向いている段**：L1・L2（進行と例外対応）。L3 以降は、Hermes が載せているモデル次第。

## agy（Antigravity CLI）

- **起動**：作業フォルダで `agy` を起動する。**agy は作業フォルダの AGENTS.md を自分で読む**（Novel_5 で確認）。だから、試験のサンドボックスは「AGENTS.md と道具だけがある、余計なもののないフォルダ」にしてある。リポジトリ直下で起動すると、作品フォルダの AGENTS.md（進行役用）と混ざるので注意。
- **プロンプトの渡し方**：`agy -p -` は標準入力を読まない（`-` を文字として受け取る）。開始プロンプトは引数に直接書くか、対話で貼る。
- **モデル名**：`Claude Opus 5.5 (Medium)` の形で指定する。定額の枠を使い切ると約5時間止まるので、L3B・L4 のように長い試験は、枠の残りを見てから始める。
- **出力の上書き**：agy は指示以上に動いて、リダイレクト先のファイルを上書きしたことがある。開始プロンプトの「状態ファイルを手で書き換えない」を外さないこと。試験の check.py は、保護ファイルの指紋と状態の整合で、上書きを見つける。
- **向いている段**：L3B（BRIEF を自分で書く）と L4（道具の改修）。Opus を載せた agy は「Claude Code 以外のハーネス × 同じモデル」の比較になり、ハーネスの差だけを測れる。

## omp

- **起動**：作業フォルダで起動し、開始プロンプトを貼る。AGENTS.md を自動で読む設定なら二重に読んでも害はない。
- **権限**：opencode.json の形の許可表を読むなら、TOOLS.md 第2節の例をそのまま使う（`approve-canon`・`guard.py seal`・`.env` を deny、`engine * start` と `status` を allow、`rescue_*`・`resolve` は ask）。許可表を持たないなら、Hermes と同じく AGENTS.md と道具側の歯止めに頼る。
- **安いモデルで動かす場合**：思考型のモデルは出力枠を推論に使い切って空の応答を返すことがある（glm-5.3、kimi-k3 で実測）。進行役には推論を切れるモデル、または推論の量を指定できるモデルを使う。
- **向いている段**：L1・L2 を安いモデルで。「進行役は Flash 級でも外れない、ただし確認の層があるとき」（Novel_4 の結論）の検証になる。

## 試験の回し方

```
python3 harness/exams/setup.py L1 ~/novel-exam/hermes-L1          # サンドボックスを作る（表示された mock のコマンドも実行）
# → ハーネスを ~/novel-exam/hermes-L1 で起動し、共通の開始プロンプトを貼る
python3 harness/exams/check.py L1 ~/novel-exam/hermes-L1          # 採点（exam_result.json にも残る）
```

L2 は A のあとで `check.py L2 <dir> --give-b` で人の指示 B を足し、ハーネスに「TASK.md の B を読んで続けて」と伝え、最後に `check.py L2 <dir> --stage B`。
結果は SCORECARD.md に一行ずつ足していきます。
